# 高影响事实的源码复核（C01–C30）

> - **对象**：4 份对抗审查（`process-consistency.md`、`soundness.md`、`concurrency-performance.md`、`behavioral-fidelity.md`）里，一旦采纳就会改变架构的 30 条事实。
> - **做法**：1 名 `claude-opus-5-5` 复核者（max effort）在基线 `7d907abfa` 上逐条找反证：读源码、预处理一个真实的 unity 编译单元、反汇编原版二进制 `build_release/src/observer/seekdb` 里的单个函数、在临时目录编译几段小程序。没有改动仓库，没有构建项目。临时程序和完整的 FMA 扫描结果留在复核时的临时目录，没有入库；复现方法写在每行的 Evidence 列里。
> - **结论**：27 条成立，3 条部分成立（C02、C20、C30），没有被推翻的。设计文档 v0.2 已按下表修正：`ObItemType` 是两份定义加一个转发头，取值不同（C02）；`eval_param_value` 约 134 处（C01）；浮点转窄整型在 C++ 里是未定义行为，结果取决于代码生成（C20）；可变静态量实际约为原估计的十倍（C30）。
> - **额外发现**：`ObKVCacheHazardSlot::retire` 不比较 `min_version` 就释放节点（C06 的 Note 列），疑似释放后使用。设计文档 0.8 把它列为 `FIXED(port)`，并作为新的疑似 bug 提交给你。
