## AREA: runtime
**What it is:** The runtime is the layer under SQL and storage that owns threads, memory accounting and allocators, disk IO, the hand-off of network requests to SQL worker threads, timers and the background DAG scheduler, the int-return-code error convention, crash and signal handling, and configuration parameters. In this branch it is already single-tenant and single-node: the TG thread-group framework, MTL tenant lookups and the RPC framework were deleted, and the MySQL network front end is the existing Rust crate rust/sql-nio (mio, no async runtime) called from C++ over a C ABI.

**Summary:** The runtime is about 94k hand-written lines plus 31k generated, 3k data and 3k vendored, and recent commits have already made it simple: the TG thread-group framework (8d49c42e7), multi-tenancy/MTL (03b513560, 3609383cd) and the RPC framework (ee560bb45) are gone. What is left is a plain single-process design: every thread goes through lib::Thread, a Rust sql-nio reactor pushes requests into one priority queue served by a pool of blocking ReqWorker threads, 58 ObTimer objects share one ObTimerService, one DAG scheduler runs compaction/DDL work, and disk IO uses libaio on Linux with condvar waits. That thread and IO model maps directly onto Rust std threads, Mutex/Condvar and channels; nothing in it needs async, and the existing sql-nio crate already uses mio with plain threads. Memory is the part that does not keep its shape: ob_malloc returns NULL at the server or per-ctx hard limit (after first trying to evict KV cache), callers turn that into OB_ALLOCATE_MEMORY_FAILED at 4,976 sites, every container insert returns int (7,135 push_back calls), and most objects live in ObArenaAllocator arenas whose free() is a no-op. Stable Rust collections abort on OOM and the Allocator trait is nightly-only, so a port has to choose between try_reserve-style fallible APIs with custom arena-aware collections, or a global allocator that blocks like today's glibc malloc hook (which already retries forever every 10ms). The sql-nio crate already takes the try_reserve route. Per-thread ambient state (THIS_WORKER, the CURRENT_CONTEXT stack of Flow objects, thread-locals in 126 files, and context macros that read and write the caller's local ret) plus 122 global service slots bound at runtime are what make a line-by-line translation non-idiomatic; in Rust these become explicit context arguments or scoped guards. The error convention is the easiest part: 80,001 `if (OB_FAIL(...)) {` blocks, 89% with empty bodies since 8a8d6f5a8 removed 55,206 LOG_WARN lines, become `?`. But about 6,000 uses of error codes as normal outcomes (OB_ITER_END, OB_ENTRY_NOT_EXIST, OB_HASH_NOT_EXIST, OB_EAGAIN) should become Option or enum results, and the 1,546 codes must stay stable because 142 of 283 CI tests check errors. Two-phase init (is_inited_ in 1,071 files) and locks declared next to the data they guard (at least 546 declarations in 284 files) are defensive patterns Rust would remove, but moving fields under Mutex<T> is a per-class restructuring. Intrusive lists, manual refcounts, raw parent/child DAG graphs, hazard-version reclamation and siglongjmp-based crash recovery need unsafe code or a redesign. The bug history has fixes of exactly the kinds Rust's ownership and Send/Sync rules prevent: a worker list changed without its lock, a worker double free, and arena-lifetime use-after-frees. All CI tests are end-to-end mysqltests, so they survive an internal rewrite as long as error codes, parameter names and DEBUG_SYNC point names are preserved.

**Structure call (surveyor):** Split verdict. The process/thread model, timers, IO manager thread layout, signal threads, configuration table and the network hand-off can keep their structure: they are OS threads, queues, condvars and a parameter table, and map onto std::thread, Mutex/Condvar, channels and a declarative macro (or build script) for the 289 parameters, with no need for an async runtime (sql-nio already runs on mio with plain threads). The error convention also keeps its structure mechanically (the OB_FAIL chains become `?`), though error-codes-as-outcomes should become Option/enum. Memory management and the ownership model built on it force a redesign: fallible allocation everywhere (NULL -> OB_ALLOCATE_MEMORY_FAILED, int-returning push_back), polymorphic ObIAllocator where free() may be a no-op, arena-owned object graphs, a thread-local stack of memory contexts driven by macros that write the caller's ret, per-thread THIS_WORKER state, 122 mutable global service slots, locks separate from data, intrusive lists, manual refcounts and a raw-pointer DAG graph. Translating these one-to-one gives unsafe-heavy Rust with raw pointers everywhere; idiomatic Rust needs an explicit context/allocator parameter, arena lifetimes or index-based graphs, Mutex<T>-wrapped state, and a decided OOM policy (fallible try_reserve-style APIs and custom collections for query memory, plus a global allocator that blocks or aborts for everything else). Files that force the call: src/oblib/lib/rc/context.h, src/oblib/lib/allocator/page_arena.h, src/oblib/lib/alloc/ob_malloc_allocator.cpp with src/oblib/lib/resource/ob_resource_mgr.cpp, src/oblib/lib/worker.h, src/share/rc/ob_server_runtime.h, src/data_plane/api/data_plane/scheduler/ob_dag_scheduler.h, src/share/io/ob_io_define.h.

**Structure call check (verifier):** I agree with the split verdict, with three changes. (1) The memory half still forces a redesign, but for a partly different reason. The survey's central example (ob_malloc returning NULL at a server-wide limit enforced in ObMemoryMgr::update_hold) is not the default runtime. Linux and macOS builds default to jemalloc (CMakeLists.txt:213-214, deps/external/CMakeLists.txt:17-19, ob_malloc.cpp:147-151), and there ob_malloc/ObMallocAllocator/the malloc hook call je_malloc directly with no limit check (ob_malloc.h:118-125, ob_malloc_allocator.cpp:67-70, malloc_hook.cpp:163-164). What stays is the int/NULL-return convention at about 5k sites, module budgets that return NULL (ob_block_alloc_mgr.h:38-49; memstore, KV cache and vector limits from commit 38bd9c622), polymorphic ObIAllocator with no-op free (page_arena.h:1020), the thread-local context stack with ret-writing macros (context.h:65-67), intrusive lists and manual refcounts. Those still rule out an idiomatic one-to-one translation. But it means a Rust port can do what the C++ already does: jemalloc as the global allocator, aborting on true OOM, with budgets as explicit fallible allocator objects only where query memory is bounded. That is less work than the 'fallible everywhere' reading suggests. (2) The thread side keeps its structure more easily than the hard parts imply. Custom mmap'd stacks are used only on Linux (thread.cpp:84-118); macOS, Android and Windows already use pthread_attr_setstacksize, which std::thread::Builder::stack_size covers. (3) The thread/timer side has more mechanisms than the survey names: ObTimeWheel, ObDedupQueue, ObUniqTaskQueue, ObAsyncTaskQueue, ObDynamicThreadPool, ObMapQueueThreadPool, ObOccamThreadPool, ObLightyQueue, and ObIndependentDag run by ObDDLDagThreadPool (src/storage/ddl/ob_ddl_dag_thread_pool.h:29). They can keep their shape, but a port should merge them into a few Rust primitives rather than translate each one. The signal half is smaller than stated because do_with_crash_restore is dead code, so siglongjmp is only in memory_dump.cpp. The network hand-off, errno table and parameter table keep their structure as the survey says.

**Hard parts:**
- Fallible allocation as the normal path: 4,976 OB_ALLOCATE_MEMORY_FAILED sites and int-returning container ops (src/oblib/lib/container/ob_array.h:304); stable Rust Vec/Box/String abort on OOM and the Allocator trait is nightly-only (assumption from Rust docs), so ports need try_reserve discipline or custom collections such as allocator-api2/hashbrown-style containers.
- Memory accounting and limits inside the allocator, with cache eviction on the failure path: src/oblib/lib/resource/ob_resource_mgr.cpp:54-86 and :201-254, src/oblib/lib/alloc/ob_malloc_allocator.cpp; a Rust #[global_allocator] cannot return an error to the caller, only NULL -> handle_alloc_error.
- Polymorphic allocator where free() may do nothing and objects are placement-new'd into arenas without destructors: src/oblib/lib/allocator/page_arena.h:975-1029, src/oblib/lib/alloc/ob_iallocator.h; Rust needs arena lifetimes ('a references, bumpalo-style) or indices.
- Thread-local memory-context stack and for-loop macros that assign the caller's ret: src/oblib/lib/rc/context.h:46-73, :700-760.
- Per-thread worker state reached from anywhere: THIS_WORKER (src/oblib/lib/worker.h, Worker::self_ __thread, 396 uses), ObMallocHookAttrGuard thread-local memory attr (src/oblib/lib/alloc/malloc_hook.cpp:79), ObPageManager::thread_local_instance (src/observer/omt/ob_th_worker.cpp).
- Mutable global service slots bound and cleared at runtime: src/share/rc/ob_server_runtime.h:126-148 (122 types, 1,243 call sites); OnceLock does not support unbinding, so this needs explicit context passing or atomic pointer slots.
- Intrusive lists and CONTAINER_OF: ObDLinkBase (71 files), ObDList (77 files), src/observer/ob_srv_deliver.cpp repost(); worker list in src/observer/omt/ob_server_runtime.h (WList workers_).

**Open questions:**
- Whether the memory limit holds under MALLOC_BACKEND=jemalloc: the jemalloc branch of ObMallocAllocator::realloc skips update_hold. jemalloc hooks or extent limits configured elsewhere were not checked.
- How many threads a running server actually has, and of which kinds; this needs a live process (thread list or virtual table), not a read-only look at the source.
- Whether the embedded form always runs as a separate server process (run/seekdb.clients, wait_no_client, _Exit in src/observer/ob_server.cpp:1670-1680) or must also load into a host process. This decides whether a Rust port may own signal handlers, the global allocator and panic=abort.
- How much vendored C/C++ code (zstd, ICU and others) depends on the glibc malloc hook for memory accounting. A Rust #[global_allocator] does not see C allocations unless the hook is kept.
- Which of the 500 tools/obtest tests still run against seekdb, since CI does not use them.
- Whether the 206 latch ids and wait-event statistics (ObLatchIds, ObWaitEventIds) are user-visible through virtual tables that tests or users depend on. If so, a Rust Mutex<T> port has to keep that instrumentation.
- Whether ReqWorker latency and fairness (100ms poll, adaptive expansion, mclock IO scheduling in src/share/io/io_schedule) can be matched and checked without a benchmark run. This cannot be settled read-only.

**Verifier's trust note:** For raw counts and code structure, the survey can be trusted. Almost every count reproduced exactly, or within a few percent, with a different method (line and distinct-file counts instead of -c sums, a Perl pass instead of awk, a function list pulled from nio.h). Every cited path and line number I opened says what the survey claims, and the six bug-fix commits exist with the stated contents. Its weak spot is the memory section, which matters most for the decision. It presents the obmalloc path (server hard limit, KV-cache washing, a malloc hook that retries forever) as how the server behaves, but Linux and macOS builds default to jemalloc, where none of that runs and limits are per-module budgets. The redesign verdict for memory still holds because of the int/NULL-return convention, arenas, context macros and intrusive structures, but the reasoning and the proposed OOM policy have to be restated from the jemalloc default. Smaller problems: several counts come from loose regexes (nio_* calls 61 vs 37, O_DIRECT 76 vs 54, lock declarations 546 vs about 460, context macros 175 vs about 49 ret-writing uses); the CI test count is 272, not 283, and two cited example tests are not run; the sql-nio 'already fails softly' claim is overstated; do_with_crash_restore is dead code; and the size split leaves out containers, hash and the KV cache that the argument depends on. Two open questions can be settled from the source. The embedded mode is a flag on the seekdb executable (ob_command_line_parser.cpp:364; the only shared library, liboceanbase.so, is a Linux pretest target), and latch ids are no longer user-visible. Use the survey's numbers and structure description as they are, but re-derive the allocator/OOM section before it feeds the migration decision.
