## AREA: deps
**What it is:** seekdb links about 19 prebuilt third-party libraries, listed in deps/init/*.deps (13 platform files) and wired in mainly through src/oblib/CMakeLists.txt, src/oblib/lib/CMakeLists.txt and src/oblib/grpc/CMakeLists.txt. It also carries about 34k lines of copied third-party C/C++ source (zstd 1.3.8, xxHash, IANA tzcode, libeasy/libev headers, CRC code) plus about 13k lines of checked-in protobuf/gRPC output. Most libraries are called from a small number of wrapper files. The exceptions are boost::geometry, which runs through src/share/geo, and vsag, whose C++ interfaces seekdb subclasses.

**Size split:** Library code itself is outside the tree (prebuilt packages under deps/3rd, not git-tracked). The in-tree lines that belong to this area break down as follows.

**Summary:** 1. The dependency surface is smaller than the manifests suggest, and it keeps shrinking. LLVM is now only the compiler toolchain: the PL JIT was removed in 3f1fbb84f (-62,423 lines), and src/objit is a single enum header. The compression libraries were cut down to none/zstd138 in 4238c88e9 (-53,912 lines). abseil, xz and gtest have no direct users.

2. ICU is not used for charsets or collations. Those are 24,815 lines of in-tree, MySQL-style code in src/oblib/lib/charset. ICU is only the regex engine behind REGEXP (the uregex_* C API in ob_expr_regexp_context.cpp) plus one URL-codec call. So ICU stays a plain C-FFI dependency, while the charset code is translation work that belongs to oblib.

3. Most C dependencies are called from 1-8 wrapper files each and have mature Rust answers:
   - openssl → RustCrypto crates plus rustls, which sql-nio already uses.
   - libcurl → reqwest or the curl crate.
   - sqlite → rusqlite, which reads the same meta.db format.
   - zlib → flate2.
   - libaio → io_uring or libc syscalls.
   - jemalloc → tikv-jemallocator. It is already built through Cargo.
   - protobuf-c → prost.
   - gRPC/protobuf → tonic/prost. That removes 12,345 checked-in generated lines.

4. Three dependencies decide the structure:
   - boost::geometry is header-only C++ templates. It is specialized over seekdb's own geometry types (ob_geo_bin_traits.h, ob_geo_tree_traits.h) and uses ellipsoid ("geographic") strategies. Its exception types leak into user-visible error codes (OB_ERR_BOOST_GEOMETRY_*).
   - vsag is C++ with virtual Allocator, Logger and Filter interfaces that seekdb subclasses in 4 places. vsag's own C API does not cover allocators, loggers, extra-info, iterators or sparse vectors.
   - relaxed-rapidjson is a header-only fork with non-standard parse flags.
   None of the three can be called over FFI without a C++ shim, and no Rust crate matches their behavior.

5. Several dependencies are tied to on-disk formats, so replacing them is a compatibility question and not just a code question. S2 cell ids are written into spatial-index rows; vsag index snapshots are persisted (see the legacy-format fix 50306fbfd); zstd 1.3.8 compresses blocks; the CRC-32C-based ob_crc64 produces checksums; and sqlite stores meta.db.

6. About 34k lines of copied third-party code can be deleted and replaced by crates: zstd, twox-hash/xxhash-rust, chrono-tz/tz-rs, crc32c, and removing the vestigial libeasy headers. The ~39k-line embedded tz table becomes a crate dependency.

7. The strongest case-for-leaving evidence from this area is the in-house memory-safety toolchain: the ob-sanity LLVM pass plugin plus jemalloc-level shadow memory. Commit 6da784ac1 fixed a wrong buffer length, a read after unlock and a dangling pointer, all found with it.

8. Public-surface tests cover boost/S2 heavily: 42 geometry test files, whose 42 result files total 55,904 lines and include results carried over from MySQL. vsag has 31 tests. There are 6 REGEXP tests. libxml2, protobuf-c (ST_AsMVT) and the zlib COMPRESS() function have none.

**Structure call (surveyor):** This area does not translate one-to-one. Each dependency needs its own decision, and they fall into four kinds.

(a) C libraries with a mature Rust crate or plain C FFI can be swapped behind their current wrappers without changing structure:
- OpenSSL → RustCrypto crates (md-5, sha1, sha2, aes, des, hmac) plus rustls.
- libcurl → reqwest, or the curl crate.
- sqlite → rusqlite, same meta.db file format.
- zlib → flate2.
- libaio → io-uring or libc syscalls.
- jemalloc → tikv-jemallocator.
- libunwind → keep over FFI, because backtraces taken inside signal handlers need it.
- CRoaring → croaring (the same C library) or roaring.
- protobuf-c → prost.
- gRPC/protobuf → tonic + prost.
- ICU regex → keep ICU4C over its C API, since no pure-Rust regex matches ICU semantics.
- fast_float → Rust std float parsing.

(b) Copied third-party source is deleted and replaced by crates:
- zstd → zstd or ruzstd.
- xxHash → xxhash-rust.
- tzcode and the tz data → chrono-tz or tz-rs.
- CRC → crc32c / crc64fast.
- libeasy/libev headers → std::net types.
Each replacement must give bit-exact output wherever the result is persisted.

(c) Three dependencies force a redesign, because they are header-only or virtual-interface C++ and no Rust crate behaves the same:
- boost::geometry, including ellipsoid ("geographic") strategies and user-visible exception-to-error mapping. Options: keep it behind a hand-written C++ shim that instantiates the templates for seekdb's geometry types, or move to geo + geographiclib-rs + proj and accept different numeric results.
- vsag. Needs a C shim that turns its Allocator, Logger and Filter subclasses and its std::istream/ostream serialization into function-pointer callbacks.
- relaxed-rapidjson. Needs a hand-written Rust SAX parser that reproduces the fork's flags.

(d) S2 is C++ as well, but its surface is small (1,343 lines). It needs either a small C++ shim or the partial pure-Rust s2 crate, and in either case the cell coverings must stay identical, because cell ids are stored in index rows.

Files that force the redesign: src/share/geo/ob_geo_dispatcher.h, src/share/geo/ob_geo_bin_traits.h, src/share/geo/ob_geo_tree_traits.h, src/oblib/lib/vector/ob_vsag_adaptor.cpp, src/storage/allocator/ob_vector_allocator.h, src/oblib/common/json_type/ob_json_parse.cpp.

**Structure call check (verifier):** I mostly agree. This area needs one decision per dependency, not a line-by-line translation. boost::geometry and vsag are the two real redesign points. The evidence: bg:: and boost:: are used in 39 files, with traits in ob_geo_bin_traits.h and ob_geo_tree_traits.h and the dispatcher in ob_geo_dispatcher.h:1314-1363. vsag is reached through C++ virtual subclasses in ob_vector_util.h:35, ob_vsag_adaptor.cpp:87, ob_vector_allocator.h:71 and ob_vector_index_adaptor.h:237, and through std::istream/ostream serialization, while vsag_c_api.h offers only 'bool (*)(int64_t)' as a callback. Five adjustments. (a) relaxed-rapidjson does not belong in the same bucket as boost and vsag. The fork's full reader.h (2,417 lines) is installed and readable, it is used from 7 files through one SAX wrapper (ob_json_parse.cpp), and Windows already ships without the relaxed flags. **Hard parts:**
- boost::geometry is header-only C++ templates, specialized over seekdb's own geometry binary and tree types through traits (src/share/geo/ob_geo_bin_traits.h has 56 template lines; ob_geo_tree_traits.h has 46). src/share/geo/ob_geo_dispatcher.h (256 template lines) sends each geometry-type pair and coordinate system to the right function. None of this can be called from Rust without a C++ layer that instantiates every combination.
- Geographic-coordinate results must match MySQL. src/share/geo uses srs::spheroid, geographic_winding, geographic_segments and andoyer strategies. The Rust geo crate is mostly planar, and geographiclib-rs covers geodesic distance and area but not intersection, within or difference on an ellipsoid. The expected results in tools/deploy/mysql_test/test_suite/geometry/r (55,904 lines, partly from MySQL, e.g. r/mysql/st_buffer_mysql.result) pin the numbers.
- Error codes follow boost's exception types: src/share/geo/ob_geo_dispatcher.h:1316-1359 maps them to OB_ERR_BOOST_GEOMETRY_* (src/share/ob_errno.h:2533-2541). Any replacement must reproduce when these user-visible errors are raised.
- S2 cell coverings are persisted as spatial-index keys (src/sql/das/ob_das_domain_utils.cpp:168-193). A pure-Rust S2 must produce the same S2RegionCoverer output (src/share/geo/ob_s2adapter.cpp) as S2 0.10.0, or existing spatial indexes become invalid.
- The vsag boundary calls back into seekdb code. vsag::Allocator is implemented in src/storage/allocator/ob_vector_allocator.h:71 and src/query/api/query/vector/ob_vector_index_adaptor.h:237; vsag::Filter in src/oblib/lib/vector/ob_vsag_adaptor.cpp:87; vsag::Logger in src/oblib/lib/vector/ob_vector_util.h:35. Serialization goes through std::ostream/istream (fserialize/fdeserialize). vsag's own C API has no hooks for any of these, so a seekdb-owned C++ shim is required.
- The C++-stream boundary is where a real out-of-bounds read happened: d08a76bce (2026-08-20) worked around vsag's BufferStreamReader treating one shard length as the full stream length when reading seekdb's ObIStreamBuf. The Rust-to-C shim would sit on exactly this seam.
- vsag snapshots are persisted, and the format is locked (commit 50306fbfd, 'use legacy VSAG serialization format', in src/oblib/lib/vector/ob_vsag_adaptor.cpp). Replacing vsag with a Rust ANN crate such as hnsw_rs or instant-distance would need a way to read existing indexes.
- CRoaring out-of-memory handling depends on C++ exceptions unwinding through C frames (src/share/roaringbitmap/ob_rb_memory_mgr.cpp: `throw std::bad_alloc()` inside roaring_malloc; 44 CROARING_TRY_CATCH sites). Rust aborts when a panic crosses extern "C", so the Rust design needs a different error path, for example fallible allocation in the pure-Rust roaring crate.
- Process-wide malloc interposition with memory attributed by thread-local labels (src/oblib/lib/alloc/malloc_hook.cpp:339-342; ObMallocHookAttrGuard used 103 times in 36 files). This is how memory that C libraries allocate gets charged to modules, and Rust's #[global_allocator] does not cover allocations made inside C libraries.
- relaxed-rapidjson is a header-only template fork whose non-standard flags (src/oblib/common/json_type/ob_json_parse.h:28-30) are implemented in a package whose source is not in the tree. A Rust parser must reproduce case-insensitive keywords, unquoted keys, relaxed numbers and the syntax-error message text.
- libxml2 is used as a SAX tokenizer that reads parser internals (ctxt->input, 7 uses, through libxml/parserInternals.h in src/oblib/common/xml/ob_libxml2_sax_handler.cpp). Moving to quick-xml means re-deriving the XML declaration and entity handling that is currently read out of libxml2's internal state.
- Persisted checksums and hashes must be bit-exact: ob_crc64() calls ob_crc64_sse42 (src/oblib/lib/checksum/ob_crc64.cpp:292), which uses the CRC-32C instruction (_mm_crc32_u64, line 365). murmurhash appears in 152 files, and XXH64 in 14 files including blocksstable bloom filters. zstd 1.3.8 compresses storage blocks through ObZstdWrapper with custom memory callbacks (src/oblib/lib/compress/zstd_1_3_8/ob_zstd_wrapper.cpp).
- Two TLS/crypto stacks in one binary: OpenSSL 1.1.1u for gRPC TLS (src/oblib/grpc/ob_grpc_context.cpp), telemetry HMAC and the SQL encrypt functions, and rustls+ring in rust/sql-nio. Converging on one is extra work.
- ICU regex has no pure-Rust equivalent. The regex crate lacks backreferences and lookaround; fancy-regex differs in syntax and behavior. ob_expr_regexp_context.cpp also relies on uregex_setStackLimit, uregex_setTimeLimit and uregex_appendReplacement semantics, so ICU4C stays behind C FFI.

**Pain instances:**
- Commit 6da784ac1 (2026-08-19) fixed three memory-safety defects found with the in-house Sanity LLVM pass (the ob-sanity dependency). (1) src/observer/virtual_table/ob_table_columns.cpp:603 passed buf_len instead of extra_print_buf_size to databuff_printf, so the write could overflow the buffer. (2) src/sql/plan_cache/ob_plan_cache.cpp read a cache object's allocator totals after unlocking the node, while a concurrent eviction could free it. (3) src/sql/plan_cache/ob_ps_cache_callback.h dereferenced ps_item_ after the item could already be erased. Rust's bounds checks, lock guards that own the data, and borrow rules rule out all three kinds of mistake.
- The existence of ob-sanity itself (deps/init/*.deps, CMakeLists.txt:223-263) and commit a0d8e61ca (2026-09-01, 'support Sanity with jemalloc': shadow memory, jemalloc extent hooks, --wrap=memcpy and friends) are standing costs paid to find memory errors that safe Rust would not produce.
- Commit ae6edddba (2026-07-13, 'Fix sanity startup crash in pre-main THP init') removed an __attribute__((constructor(101))) from src/observer/main.cpp because it ran before the runtime was ready. 9 __attribute__((constructor)) sites remain in src, e.g. ob_global_init_crc64_table in src/oblib/lib/checksum/ob_crc64.cpp. src/observer/CMakeLists.txt:17 notes that malloc_hook 'conflicts with LLVM's early global constructors on macOS'. Rust has no code that runs before main, so this whole class of problem goes away.
- src/share/roaringbitmap/ob_rb_memory_mgr.cpp contains defensive code: seekdb's allocator callback throws std::bad_alloc through CRoaring's C frames, and it is caught at 44 CROARING_TRY_CATCH call sites. roaring_free also picks the allocator from the thread-local label at free time, so an allocation made under one label and freed under another goes to the wrong allocator (a hazard; I found no bug report for it). With a Rust bitmap crate that uses the Rust allocator, the wrappers disappear. Caveat: Rust's default reaction to running out of memory is to abort, not to return an error.
- src/oblib/lib/json/ob_json.h:22-35 replaces POSIX regcomp/regexec on Windows with stubs that always return -1, so RegexFilter silently never matches on that platform. A portable Rust regex crate removes the need for such a stub. The Windows manifest also pulls in the dirent and pthreads compatibility libraries (deps/init/oceanbase.windows.x86_64.deps), used by 9 files that include dirent.h and 39 that include pthread.h. Rust's std covers both.

**Open questions:**

Or is being able to decode old blocks enough? If decoding is enough, the zstd crate, which bundles a newer libzstd, is a drop-in replacement.
- Are roaring64 bitmaps persisted anywhere, for example vector-index valid-id bitmaps? If so, does the pure-Rust roaring crate's 64-bit serialization match CRoaring's portable roaring64 format?
- Which ICU regex features actually work with libicustubdata linked, and therefore what a replacement has to match? This needs a runtime test.
- Are the 145+8 primary_standby/stanby tests in tools/obtest run against seekdb's gRPC StandbyService, or are they legacy OceanBase cases? They are not wired into the documented obd.sh mysqltest flow.
- What third-party set does the embedded form link? I found no embedded-library target in this worktree's CMake, only the imported/shared 'oceanbase' target in src/observer/CMakeLists.txt:27-43.
- Is exact numeric agreement with MySQL on geographic results a product requirement? If yes, boost::geometry has to stay behind a C++ shim; if no, geo, geographiclib-rs and proj become viable.
- The source of the relaxed-rapidjson fork (which implements the flags 1024, 2048 and 4096) and of the vsag build are outside the tree, so the exact behavior a Rust port must match cannot be read here.
- What are the provenance and license of src/oblib/lib/charset (24,815 lines) and the SHA1 in ob_encrypted_helper.cpp? They look like ports of MySQL strings/ and RFC 3174 code, but the original headers were replaced with the OceanBase Apache header.
- Are grpc 1.46.7 and libcurl 8.12.1 built against the end-of-life OpenSSL 1.1.1u package or against their own TLS? That decides whether dropping OpenSSL is possible before those two are replaced.
