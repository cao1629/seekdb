## Corrections to the feasibility report

- 2026-09-24, Decision 15's exception dropped. The report (section 6 "Before Step 1", Decision 15, and the verdict's "Start now" list) says the wasm branch's two C++ race fixes repair real races and should be merged into C++. Reading the hunks in 0be96de70 ("web assembly demo", which carries the whole wasm port, so there is no standalone commit to cherry-pick) shows both are wasm-only:
  - src/oblib/lib/list/ob_atomic_list.h: every atomic load and store of the next links is under `#if defined(__wasm__)`; native builds keep `*next`. The only native change drops a `volatile`.
  - src/oblib/lib/oblog/ob_ringbuf_log_writer.cpp: on aarch64, `WEAK_BARRIER()` is already `__sync_synchronize()` (src/oblib/lib/atomic/ob_atomic.h:34-35), and the consumer already reads the whole 64-bit header with `ATOMIC_LOAD_ACQ` (lines 321-323); on x86_64 the compiler barrier is enough. The torn bitfield write only happens on wasm32. The patch applies cleanly, but it fixes nothing on the native targets.
  So neither goes into the frozen base: the C++ reference stays exactly 834bbee1e. If wasm comes back into scope, these hunks belong to the wasm work.
