# reset

Classification vocabulary for the sweep list `reset` (migration/inventory/sweep/reset.tsv). A classifier who reads this file, the rules it cites and the site writes one inventory row per sweep row, in the seven columns of templates/inventory.tsv.

## 1. What the list holds and what its rows decide

- **Definition:** migration/inventory/sweep/summary.tsv, row `reset`: every `ret = OB_SUCCESS` on a code line that is not a declaration (also inside `FALSE_IT`), `ret = 0` in a function whose ret holds codes, and every ternary that assigns OB_SUCCESS to ret. A reset inside a `#define` body is one row per body line, and the uses of the macro are not rows. The sweep's columns are file, line, symbol, construct, text.
- **Size at 834bbee1e** (run from migration/inventory/sweep/): 3,028 rows (`sed 1d reset.tsv | wc -l`) in 862 files (`cut -f1 reset.tsv | sed 1d | sort -u | wc -l`). By construct (`awk -F'\t' 'NR>1{c=$4; sub(/ \[not built\]/,"",c); print c}' reset.tsv | sort | uniq -c`, the "statement spans lines" variants added to their kind): 2,902 `ret = OB_SUCCESS (line start)`, 13 after other code on the line, 4 inside `FALSE_IT`, 2 `ret = 0`, 76 conditional resets, 23 codes chosen by a flag, 8 errsim injection points. 60 rows sit in `#define` bodies (`awk -F'\t' 'NR>1 && $3 ~ /^#define/' reset.tsv | wc -l`) and 22 carry `[not built]`. 63 rows are in files of units that migration/not-translated.tsv lists: 35 deferred, 22 dead, 6 island (the command is under NOT_TRANSLATED).
- **What the rows decide** (RULEBOOK section 5, the row for ret-compare.tsv, reset.tsv and tmp-ret.tsv): what each code means at the site (end of data, lookup outcome, buffer too small, retry, becomes a warning, ignored, renamed), and whether a code-holding field is `ObResult` or `i32` (RULEBOOK 2.1). s2-errors.md 2.13 lists what a row records: the code or codes, what the code means there (the same list, plus "other"), and for code-holding fields `ObResult` or `i32`.
- **What is the same for every real reset:** it becomes `ret = Ok(());` at the same place (RULEBOOK 2.1, the row "`ret = OB_X;`, `ret = OB_SUCCESS;` ..."); the tests in front of it are written as the C++ writes them, never as `map_err` or `if let Err(e)` (RULEBOOK 2.1, the row on renames and resets; s2-errors.md 2.15 objection 7); and the function takes the local-ret form, since s2-errors.md 2.3 requires it for "one that has a code test on `ret`, a reset, ...". So the classification records what the cleared code meant, which the joint audit checks and which the core APIs must keep answering (s2-errors.md 2.4 rule 2). The target_translation carries what does change the Rust: how ret is held, a second holder that receives the code, a macro body, an errsim block, a declaration, or no translation at all.
- **"renamed" is not a value of this list.** A reset turns a code into success, never into another code. When a ternary clears one code and renames the others (`ret = OB_HASH_EXIST == hash_ret ? OB_SUCCESS : OB_ERR_UNEXPECTED`, src/share/schema/ob_schema_mgr.cpp:1451), the row takes the value of the cleared code and its evidence names the rename, which is also a row of ret-compare.tsv.

## 2. How to fill the seven columns

- **file**, **symbol**: copied from the sweep row. The symbol is the sweep's (`Class::function`, or `#define NAME` for a macro body).
- **source_construct**: `line N: ` and then the sweep row's construct, unchanged (`[not built]` and "statement spans lines" included), N being the sweep's line, as ret-compare.md writes it. The line keeps the merge key (file, symbol, source_construct) unique; without it 415 keys repeat (`awk -F'\t' 'NR>1{print $1"\t"$3"\t"$4}' migration/inventory/sweep/reset.tsv | sort | uniq -d | wc -l`).
- **classification**: one value of section 4.
- **target_translation**: the Rust form of the statement, in the value's form (section 4), then what else the row decides (the holder of a copied code, the `ret` parameter, the macro), then the core-unit sentence of section 4 when the file is a core unit, ending with `Rules:` and the rules used. Keep to what the row decides: longer Rust that follows from the rulebook alone is not repeated (RULEBOOK section 5, last item).
- **evidence**: the items of section 5, in its order (the value's own items sit between `after:` and `ret:`).
- **status**: `confirmed`, or `unknown` for UNKNOWN.

## 3. How to read the site

Three facts decide every row.

1. **The tests in front of the reset**: the conditions that must hold for control to reach it, that is the innermost `if`, `else if`, `case`, loop condition or ternary that holds it and every test around that one. An `else` is read as what the earlier tests of its chain leave: after `OB_X != ret` only OB_X reaches it; after `OB_FAIL(f()) && OB_X != ret`, OB_SUCCESS or OB_X; `else if (FALSE_IT(ret = OB_SUCCESS))` sees what the tests before it leave. A reset inside no test has none.
2. **The codes that reach the reset**: the codes ret can hold when the reset runs, as those tests limit them. The tests **name** the codes when one of them limits ret to named codes: an OB_ code compared with ret or with a variable that holds a code in ret's place (hash_ret, tmp_ret, a saved copy), a `case` label of a `switch` over ret, or a predicate on ret (`is_schema_error(ret)`), which names the codes its body lists (the 24 predicates are in src/share/ob_define.h:71-265, others in their own files). They **name no code** when none of them does that: only `OB_FAIL(x)`, `OB_TMP_FAIL(x)`, `OB_SUCCESS != ret`, the `else` of a success test, conditions on other things, or no test at all. Four cases need care:
   - A test on something else inside a named-code test, or joined to it by `&&`, keeps the named codes: in `if (OB_ENTRY_NOT_EXIST == ret) { if (flag) { reset } }` OB_ENTRY_NOT_EXIST reaches the reset.
   - A named code held in another variable is the code the statement clears, even when ret itself is OB_SUCCESS there: `ret = OB_HASH_EXIST == hash_ret ? OB_SUCCESS : OB_ERR_UNEXPECTED` (src/share/schema/ob_schema_mgr.cpp:2871-2873) clears the OB_HASH_EXIST that set_refactored put in hash_ret.
   - A named-code test joined by `||` to a test on something else (`OB_ERR_BAD_DATABASE == ret || OB_INVALID_ID == extern_type_info->type_owner_`, src/pl/ob_pl_resolver.cpp:1356) still names its codes; the other side also lets through whatever ret holds when it is true, and the evidence names those codes (there, any failure of get_database_id, which sets the id to OB_INVALID_ID before it can fail, src/share/schema/ob_schema_getter_guard.cpp:543).
   - A named code that cannot reach the reset today (no callee returns it, or no path sets it) still counts, and the evidence says so and why, as example 1 does for OB_NOT_INIT. When none of the named codes can, the reset cannot run today; the row still takes the value of the named codes, and the evidence says the reset cannot run. src/storage/compaction/ob_compaction_suggestion.cpp:574-577 is one: it clears OB_SERVER_RUNTIME_NOT_READY in the `else` of SERVER_MODULE_SCOPE (src/share/rc/ob_server_runtime.h:230-232), which sets no code, so ret is OB_SUCCESS there.
3. **What ret is**: a local (`int ret = OB_SUCCESS`, `INIT_SUCC(ret)`, `int ret = OB_X`, `int ret = f()`, `int64_t ret = OB_SUCCESS`), a lambda's own local, the enclosing function's ret that a lambda captures by reference (src/share/config/ob_common_config.cpp:169, :194), an `int &ret` parameter, a by-value `int ret` parameter, or, in a `#define` body, the caller's ret, unless the body declares its own (section 6).

The sweep's construct text is a hint, not the answer. A "code chosen by a flag" ternary can overwrite a callee's code (src/sql/engine/basic/ob_json_table_op.cpp:1670), and "after other code on the line" can be a declaration the sweep did not recognise (src/storage/memtable/mvcc/ob_mvcc_trans_ctx.cpp:1947). A `LOG_WARN` is a server log line, not a warning to the user.

## 4. The values

Take the first value, in this order, whose test holds. Every row whose statement is `ret = OB_SUCCESS`, in any spelling of section 6, becomes `ret = Ok(());` at the C++ place, under the tests in front written as the C++ writes them (`matches!`, a `match` arm, `is_err()`), in a function in the local-ret form (RULEBOOK 2.1; s2-errors.md 2.3); the value's target_translation cites those rules and adds what the value decides. Values 1-4 also cover rows whose statement is not such a reset: a file left untranslated, a declaration, and a ternary whose code comes from a tracepoint or a flag.

| # | Value | Meaning |
|---|---|---|
| 1 | NOT_TRANSLATED | the file is not translated |
| 2 | DECLARATION | the line declares ret and clears nothing |
| 3 | ERRSIM_POINT | a tracepoint read in this function decides the code |
| 4 | CHOSEN_BY_FLAG | a ternary picks OB_SUCCESS or a code while ret holds OB_SUCCESS |
| 5 | ALREADY_SUCCESS | ret is OB_SUCCESS on every path to the reset |
| 6 | OWN_DEFAULT | the function's own default code is replaced by success |
| 7 | BECOMES_WARNING | the code, or another code in its place, is recorded as a warning, then cleared |
| 8 | RESTORED_LATER | the code is saved, then put back into ret or returned later |
| 9 | COPIED_OUT | the code is copied into a field, an out-parameter or a result object, then cleared |
| 10 | END_OF_DATA | an iteration ran out or was stopped |
| 11 | LOOKUP_OUTCOME | a lookup found nothing, or found the key already there |
| 12 | BUFFER_TOO_SMALL | the output or the container had no room |
| 13 | RETRY | the reset is part of trying the failed call again |
| 14 | OTHER_CODE | another named code that the site takes as a normal answer |
| 15 | IGNORED | whatever failed is dropped and the function goes on |
| 16 | UNKNOWN | the design or the site leaves the row open |

Section 6 gives the Rust for each spelling of ret and of the reset, whatever the value (`ret = 0`, `FALSE_IT`, the ternary, an `int &ret` parameter, a macro body, `#ifdef ERRSIM`).

**Core units.** 827 rows are in files of migration/core-manifest.tsv (from migration/: `awk -F'\t' 'NR==FNR{if(FNR>1){n=split($5,a,",");for(i=1;i<=n;i++){sub(/:.*/,"",a[i]);c[a[i]]=1}};next} FNR>1 && ($1 in c)' core-manifest.tsv inventory/sweep/reset.tsv | wc -l`). Core units are written against the design (RULEBOOK section 0), and s2-errors.md's rules bind the core too (its opening list), so each value's form holds where the core keeps the function; a core API that replaces a C++ API keeps that API's codes at its boundary, whatever it uses inside (s2-errors.md 2.4 rule 2). The target_translation of such a row adds `Core unit (core-manifest.tsv:<line>): this form where the core keeps the function (RULEBOOK section 0).`, the line being the entry whose `inputs` hold the row's line (some entries give line ranges).

**Resets in the functions that count references to disk blocks.** The block manager's per-block count stays a count, with the C++ codes of `inc_ref` and `dec_ref`, and the objects that take those references release them where the C++ does: an explicit release stays a call, and a destructor's release runs from `Drop`, its blocking reads and retry loops included (s3-memory.md 3.4 R1 and Example E4; RULEBOOK 2.2, the `inc_ref`/`dec_ref` row; design amendment A1-2). So `ObBlockManager::inc_ref` and `dec_ref`, `ObSSTable::inc_macro_ref` and `dec_macro_ref`, and `ObTablet::inc_macro_ref_cnt` and `dec_macro_ref_cnt` with their helpers all stay, none becomes an `Arc` clone or drop, and their resets are classified like any other. The reset at src/storage/blocksstable/ob_block_manager.cpp:637, in `ObBlockManager::inc_ref`, clears the OB_ENTRY_NOT_EXIST that the block map's `get` answers for a block it does not hold yet (src/oblib/lib/hash/ob_linear_hash_map.h:2031) and is LOOKUP_OUTCOME. The one at src/storage/tablet/ob_tablet.cpp:2201, in `dec_ref_with_macro_iter`, drops a failed `dec_ref` or `free_block` and moves to the next block, and is IGNORED; it runs on the rollback of a failed `inc_ref_with_aggregated_info` (ob_tablet.cpp:2003), an explicit call, and on the path `ObTablet::dec_macro_ref_cnt` takes (ob_tablet.cpp:2140, :2166), which the tablet's macro-reference owner's `Drop` runs.

### 4.1 NOT_TRANSLATED
- **Test:** the row's file appears in the `files` column of migration/not-translated.tsv, whatever the reason. Every `[not built]` row is one (all 22 are dead units). Command for the rows by reason, from migration/: `awk -F'\t' 'NR==FNR{if(FNR>1){n=split($3,a,",");for(i=1;i<=n;i++)r[a[i]]=$2};next} FNR>1 && ($1 in r){print r[$1]}' not-translated.tsv inventory/sweep/reset.tsv | sort | uniq -c`. An entry with a line range (`file:a-b`) covers only those lines; the files listed that way (`awk -F'\t' 'NR>1{print $3}' not-translated.tsv | tr ',' '\n' | grep ':'`), src/oblib/common/timezone/ob_timezone_info.cpp and src/storage/fts/dict/ob_ik_dic.cpp, hold no reset row.
- **target_translation:** `none: <reason>, unit <unit_id>`. Units in not-translated.tsv are not translated (RULEBOOK section 0, the three kinds of unit); an island file keeps its C++.
- **evidence:** `not-translated.tsv:<line>` with its reason. The code needs no trace.

### 4.2 DECLARATION
- **Test:** the statement declares ret (`<type> ret = OB_SUCCESS;` with a type the sweep's declaration pattern did not know, such as `bool` or `int32`), and the function stores only OB_SUCCESS or OB codes in it. A `bool ret` passes only when nothing but OB_SUCCESS is ever stored in it, because a bool turns every other code into 1; a `bool ret` that receives a code is UNKNOWN (open question 2).
- **target_translation:** `let mut ret: ObResult = Ok(());`, the returns of ret as the C++ has them. Rules: RULEBOOK 2.1 (the `int ret = OB_SUCCESS;` row); s2-errors.md 2.2 rule 5 (a local holding only codes is `ObResult`).
- **evidence:** the declared type, and each line that stores into that ret, or "no other store".

### 4.3 ERRSIM_POINT
- **Test:** a tracepoint read in this function decides the code the statement writes or clears: `ret = EN_X ? : OB_SUCCESS;` for a point declared with `ERRSIM_POINT_DEF` (the sweep's "errsim injection point" rows), or a reset whose tests test ret right after a tracepoint read was stored in it (`ret = OB_E(EventTable::EN_X) ret;`, `EVENT_CALL` or such a point), whatever ret held before that read: the tracepoint is used as a switch. For the ternary, ret also holds OB_SUCCESS when it runs (the test of ALREADY_SUCCESS); if it can hold a callee's code there, go on to values 7-15. A tracepoint read into another variable that only picks the branch does not make the row ERRSIM_POINT; the row is classified on ret's own codes: src/sql/ob_sql.cpp:2988 reads a point into tmp_ret, and the reset at :2992 is COPIED_OUT because ret was copied into the out-parameter get_plan_err at :2986.
- **target_translation:** for the ternary, `ret = ObError::from_code(<the point's value, 0 when off>);`, the value read through ob-base's tracepoint API under the point's name (RULEBOOK 2.3, the tracepoints row). `EN_X ? : OB_SUCCESS` reads the point through its `operator int` (src/oblib/lib/utility/ob_tracepoint.h:339) and has the shape of `OB_E(EventTable::X) OB_SUCCESS` (the macro at src/oblib/lib/utility/ob_tracepoint.h:127-128), which s2-errors.md 2.4 rule 8 translates as `ObError::from_code(ob_e!(EventTable::X, 0))`. For a reset: `ret = Ok(());`. Code inside `#ifdef ERRSIM` goes inside `#[cfg(feature = "errsim")]` (RULEBOOK 2.3; s8-numerics-platform.md 3, which keeps tracepoints themselves outside it).
- **evidence:** the read's line, the point's declaration (the `ERRSIM_POINT_DEF` line or the `EventTable` name), the `#ifdef ERRSIM` line if there is one, and, for the ternary, the line showing ret held OB_SUCCESS before it (an `OB_SUCC(ret)` guard or the declaration); for a switch, what ret held before the read.

### 4.4 CHOSEN_BY_FLAG
- **Test:** the statement is a ternary between OB_SUCCESS and a code (`ret = c ? OB_SUCCESS : OB_X` or the reverse, on one line or several) whose condition c does not test a code, and ret holds OB_SUCCESS whenever it runs (the test of ALREADY_SUCCESS). When ret can hold a callee's code there, the ternary clears that code or replaces it, depending on c: go on to values 7-15, with c added to the tests in front of it.
- **target_translation:** `ret = if c { Ok(()) } else { Err(OB_X) };`, arms in the C++ order, a call inside c kept in place. Rules: RULEBOOK 2.1 (`ret = OB_X;` is `ret = Err(OB_X);`, `ret = OB_SUCCESS;` is `ret = Ok(());`).
- **evidence:** the condition and what sets it, and the line showing ret holds OB_SUCCESS (the guard, the `else` of a failure test, or the declaration with no call between).

### 4.5 ALREADY_SUCCESS
- **Test:** every path into the reset leaves ret equal to OB_SUCCESS: the reset sits in a branch entered only on success (inside `OB_SUCC(ret)` or `OB_SUCCESS == ret`, in the `else` of `OB_FAIL(x)` or of `OB_SUCCESS != (ret = f())`, in a later branch of a chain whose earlier branches stop on every error), or no call or store has changed ret since it was declared or last set to OB_SUCCESS. A reset whose tests name a code (section 3, item 2) is never this value, even when ret is OB_SUCCESS there: a code held in another variable is the code the statement clears, and when no named code can arrive the reset cannot run; either way the row takes the value of the named codes.
- **target_translation:** `ret = Ok(());`, kept though it changes nothing. RULEBOOK section 0 lists the only statements a translation may remove, and this is not one of them; RULEBOOK 2.1 gives the form.
- **evidence:** the line that proves it: the guard, the earlier tests of the chain, or the declaration and the lines between.

### 4.6 OWN_DEFAULT
- **Test:** on every path into the reset, ret holds only a code this function put there with a constant, by its declaration `int ret = OB_X;` or a store `ret = OB_X;`, as the answer it gives unless a condition is met (not found, no room, try again, wrong type), and the reset says the condition was met. If a callee's code can also reach the reset, go on.
- **target_translation:** `ret = Ok(());`; the default is `let mut ret: ObResult = Err(OB_X);` or `ret = Err(OB_X);`. In a core unit the core-unit sentence applies (section 4, before 4.1), and the API keeps OB_X as its answer. Rules: RULEBOOK 2.1 (the `ret = OB_X;` row); s2-errors.md 2.2 rule 5, 2.4 rule 2.
- **evidence:** the line that stores the default, the condition that leads to the reset, and for a core API the rule or callers that rely on OB_X.

### 4.7 BECOMES_WARNING
- **Test:** the branch that holds the reset records the code, or another code in its place, as a warning, before or after the reset: a `LOG_USER_WARN`, `LOG_USER_NOTE`, `LOG_MYSQL_USER_WARN`, `LOG_MYSQL_USER_NOTE`, `FORWARD_USER_WARN` or `FORWARD_USER_NOTE` call (src/sql/engine/expr/ob_expr_regexp.cpp:149-155 records OB_ERR_INVALID_CHARACTER_STRING for OB_ERR_INCORRECT_STRING_VALUE); a call of a helper whose own body makes one (one call deep, such as `print_user_warning`); or a copy of the code into a variable or field whose name says warning (`warning = ret`) that this function never puts back into ret or returns. A copy that it does put back is RESTORED_LATER, whatever its name: src/oblib/common/wide_integer/ob_wide_integer_str_funcs.cpp:402 copies ret into `int warning` and :435 puts it back.
- **target_translation:** `ret = Ok(());` with the warning written as the C++ writes it: a user warning is `log_user_warn!(OB_X, ...)` or `log_user_note!(OB_X, ...)` (s2-errors.md 2.7 rules 1 and 4 for the `forward_user_*!` forms); a copy into a warning variable keeps that variable an `ObResult` (s2-errors.md 2.2 rule 5 names the casts' `warning`; 2.4 rule 7 gives the Rust for `get_cast_ret`). Rules: also RULEBOOK 2.1; s2-errors.md 2.3.
- **evidence:** the warning call, or the warning holder with its declaration line and the place that reads it.

### 4.8 RESTORED_LATER
- **Test:** before the reset, the branch copies ret's code into another variable (usually a local such as tmp_ret or save_ret, and also one named for warning, see 4.7), and a later statement of the same function puts the copy back into ret or returns it, on some path.
- **target_translation:** `ret = Ok(());`. A local copy is its own `ObResult` (RULEBOOK 2.1, the `tmp_ret` row); a field copy follows COPIED_OUT's holder rule. The put-back is written as the C++ writes it (`ret = tmp_ret;`); a merge that means "a unless a is success, then b" is `a.and(b)` (s2-errors.md 2.4 rule 4).
- **evidence:** the copy line, the put-back or return line, and what runs between them.

### 4.9 COPIED_OUT
- **Test:** before the reset, the branch copies ret's code into something that is not a local of this function (a member, an out-parameter, a result, task or context object), directly (`x_ = ret`) or through a call whose body stores its argument (`set_ret_code(ret)`, `switch_status(..., ret)`), and nothing in this function puts it back.
- **target_translation:** the copy and `ret = Ok(());` in the C++ order, and the holder's type, which this row decides: `ObResult` when it holds only OB_SUCCESS and codes and is neither sent nor stored; its C++ integer under its C++ name (`i32` for an `int`, `i64` for an `int64_t`) when it also holds values that are not codes or is sent or stored (serialized, in rows or packets), written as `ret.code()` (widened with `i64::from` for an `i64`) and read through `ObError::from_code`; an `AtomicI32` of the raw value when another thread reads it while this one can write it and no lock guards it. A holder that a lock guards is a plain field of the data inside that lock (its lock-guards.tsv row), written through a guard that lives exactly as long as the C++ holds the lock, which is the `sync` module's owning guard where the C++ unlocks in another function (s8-numerics-platform.md 5 rule 5, design amendment A1-8); a holder that an `ObRecursiveMutex` guards is a field of the `Mutex<T>` beside that lock, since the lock itself holds no data (s8-numerics-platform.md 5 rule 8, design amendment A1-3). If atomic-fields.tsv has a row for the holder, that row decides between atomic and locked. A holder inside an element of a hash map is written as s4-sql-front.md 2.1 rule 4 says (design amendment A1-4): through `get_2`'s `&mut V` or the `&mut HashMapPair` a callback gets; through the `Arc` or id of an element whose address the C++ stores elsewhere; or, where the value is the object a C++ pointer value pointed to, into the copy `get_refactored` returned, written back at once with `set_refactored(key, value, 1, 0, 0)` under one hold of the map's lock, on a map whose `EXTEND_RATIO` is 1. A `foreach_refactored` callback that writes one is an inventory finding to report. For example, report_bad_block stores the code it is passed (src/storage/blocksstable/ob_block_manager.cpp:1347) into the `int64_t` ObBadBlockInfo::error_type_ (ob_block_manager.cpp:570; src/storage/blocksstable/ob_block_manager.h:93) under bad_block_lock_ (ob_block_manager.cpp:559), and a virtual table sends it as a column (src/observer/virtual_table/ob_all_virtual_bad_block_table.cpp:67), so it stays an `i64` inside the lock's data. Rules: s2-errors.md 2.2 rules 5 and 6; RULEBOOK 2.1 (the rows on code-holding fields and on codes shared between threads); RULEBOOK 2.7 (a field that one thread writes and another reads is an `Atomic*` or a field inside a lock; an OB lock is a `Mutex<T>` or `RwLock<T>` that owns the data it guards, with a guard that lives as long as the C++ holds the lock; the `ObRecursiveMutex` row); RULEBOOK 2.5 (the `ObHashMap` row); s2-errors.md 2.1 (the `ErrCode` trait's `code()`).
- **evidence:** the store (in the callee when the copy goes through a call), the holder's declaration line, every place that reads it, whether it is serialized (the `OB_SERIALIZE_MEMBER` line or the encoder), which threads write and read it, and the lock that guards it, if any, with the lines where the C++ takes and releases it.

### 4.10 END_OF_DATA
- **Test:** the tests in front of the reset name the codes that reach it (section 3), and OB_ITER_END or OB_ITER_STOP is one of them. It wins over the codes of 4.11 and 4.12 named with it.
- **target_translation:** `ret = Ok(());` under the tests in front, as the C++ writes them (`matches!(ret, Err(OB_ITER_END))`, a `match` arm, or the ternary as an `if` expression). The iterator keeps answering OB_ITER_END. Rules: RULEBOOK 2.1; s2-errors.md 2.3, 2.4 rule 2.
- **evidence:** the call that returns the code, the test, and what the site does at the end: breaks, sets a flag, moves to the next child or task, or keeps the rows it already read.

### 4.11 LOOKUP_OUTCOME
- **Test:** the tests name the codes that reach the reset, none is an END_OF_DATA code, and one of them is a lookup answer: the key, name, row or position asked for is not stored, or is stored already. A lookup answer needs both (a) and (b):
  - (a) the code's name contains `NOT_EXIST`, `EXIST`, `NOT_FOUND`, `DUP`, `UNKNOWN` or `NO_SUCH`, or it is one of OB_EMPTY_RESULT, OB_READ_NOTHING, OB_EMPTY_RANGE, OB_ERR_NULL_VALUE, OB_ERR_BAD_FIELD_ERROR, OB_ERR_BAD_DATABASE, OB_ITEM_NOT_SETTED, OB_BEYOND_THE_RANGE, OB_ERR_OUT_OF_LOWER_BOUND, OB_ERR_OUT_OF_UPPER_BOUND and OB_CONFLICT_VALUE (which `ObSortedVector::insert_unique` answers for a value already stored, src/oblib/lib/container/ob_vector.ipp:482, :489);
  - (b) the code comes from a lookup: the call that produced it looks up, reads, inserts, creates or erases an item by key, id, name or position (a hash map or set, a cache, a catalog or schema guard, a result-set column getter, an inner-table or file-system read, a search in a sorted array or an index block), or passes on the code of such a call, or sets the code itself right after such a lookup finds nothing.
  - A listed code from any other producer is not a lookup answer, and the row goes on (usually to OTHER_CODE): OB_ERR_NULL_VALUE from a distance function, which answers it for a zero vector (src/data_plane/api/data_plane/vector/ob_vector_cosine_distance.h:80, cleared at src/sql/engine/expr/ob_expr_vector_similarity.cpp:131), or from gen_where, which answers it for a NULL foreign-key column (src/sql/engine/dml/ob_table_modify_op.cpp:483, cleared at :218, :331 and :403).
- **target_translation:** `ret = Ok(());` under the tests in front, as the C++ writes them. - **evidence:** the lookup call and the callee line that returns the code (or s2-errors.md 2.4 rule 2 when it names the callee's API), the test, and what the site uses on a miss or a hit (a default, a flag, a skip).

### 4.12 BUFFER_TOO_SMALL
- **Test:** the tests name the codes that reach the reset, one of them is OB_SIZE_OVERFLOW, OB_BUF_NOT_ENOUGH or OB_HASH_FULL from a writer into a buffer or container of fixed size (a printer, a serializer, `push_back` on a fixed array, a full map or queue), and none is a code of 4.10 or a lookup answer of 4.11. OB_SIZE_OVERFLOW from the stack check (`SMART_CALL`, `check_stack_overflow`) is not this value.
- **target_translation:** `ret = Ok(());` under the tests in front, as the C++ writes them. The printers keep OB_SIZE_OVERFLOW (s2-errors.md 2.4 rule 2), and so do the arrays' `push_back` (RULEBOOK 2.3); a grow-and-retry loop keeps its condition and its quirks (s2-errors.md 2.4 example 5). Rules: also RULEBOOK 2.1; s2-errors.md 2.3.
- **evidence:** the call and the buffer, and what follows: a bigger buffer and another try, a cut, or keeping what fit.

### 4.13 RETRY
- **Test:** the reset is part of trying the failed call again: it sits in a loop that makes that call again because it failed and that ends when the call succeeds (a `break` or a loop condition on success) or when a count, a deadline or a stop flag runs out, and it clears the code before the next attempt or once a later attempt succeeds; or the branch sets a variable named for retrying (`need_retry`, `retry_` and the like) that a loop or the caller tests. A loop whose rounds run whatever happened is not a retry: a thread's main loop, or a loop over items that moves to the next item.
- **target_translation:** `ret = Ok(());` under the tests in front, as the C++ writes them; the loop, its exit and any sleep stay as they are. Rules: RULEBOOK section 0 ("Keep the control flow"), 2.1; s2-errors.md 2.3.
- **evidence:** the loop's line and its exit, the sleep or back-off if any, the retry variable and where it is tested.

### 4.14 OTHER_CODE
- **Test:** the tests name the codes that reach the reset, and the tests of 4.10 to 4.13 do not hold (a listed code from a producer those tests exclude lands here).
- **target_translation:** `ret = Ok(());` under the tests in front, as the C++ writes them. Rules: RULEBOOK 2.1; s2-errors.md 2.3.
- **evidence:** the code, the callee line that returns it, and what the site does instead of failing (skips, falls back, keeps the old value).
- **A lock's `trylock` code.** `ObRecursiveMutex::trylock` keeps its code: the `sync` module's `ObRecursiveMutex` has the C++ API, and its `trylock` answers `Err(OB_EAGAIN)` while another thread holds the lock (s8-numerics-platform.md 5 rule 8; RULEBOOK 2.7, the `ObRecursiveMutex` row; design amendment A1-3). The session sweep clears that OB_EAGAIN at src/sql/session/ob_sql_session_mgr.cpp:513 and :519, after `try_lock_query` and `try_lock_thread_data` (ob_sql_session_mgr.cpp:510, :516), and leaves the busy session for the next sweep, so both rows are OTHER_CODE. The explicit unlocks stay where the C++ has them (ob_sql_session_mgr.cpp:546, :548), and the commit callback still runs after them (ob_sql_session_mgr.cpp:550-552; s8-numerics-platform.md 5 rule 5, design amendment A1-8).

### 4.15 IGNORED
- **Test:** the tests in front of the reset name no code (section 3), ret can hold an error there, and no value above applies: whatever failed is dropped and the function goes on.
- **target_translation:** `ret = Ok(());` under the tests in front, as the C++ writes them (`if ret.is_err() { ret = Ok(()); }` for `if (OB_FAIL(ret)) ret = OB_SUCCESS;`). Rules: RULEBOOK 2.1; s2-errors.md 2.3.
- **evidence:** the calls whose codes can reach the reset, and why the site goes on (its comment or its next statement).

### 4.16 UNKNOWN
- **Test:** section 7.
- **target_translation:** section 7's form, with the question.
- **evidence:** the lines that leave the row open.

## 5. What the evidence column shows in every row

In this order:
1. `sweep: reset.tsv:<N> (data row <N-1>)`, N being the line in reset.tsv.
2. **created:** the call or store that put the code in ret. For a named code, also the callee line that returns it, unless s2-errors.md 2.4 rule 2 names the callee's API (then cite the rule).

## 7. When a row is UNKNOWN

A row is UNKNOWN when:
- it is a case of an open question below;
- the tests in front of the reset, or the codes that can reach it, cannot be settled from the site and its callees, and the value depends on them (for example a code test that a macro builds from its caller's argument, when the value would change with the argument; RETRY_FUNC_ON_ERROR's reset is RETRY whatever `err_no` is, src/oblib/lib/utility/ob_macro_utils.h:674-676);
- a skeptic reviewer refutes the row with evidence and one revision does not settle it (prompt 02).

Its translation is RULEBOOK 2.10's UNKNOWN rule applied to a reset: the reset kept as `ret = Ok(());` exactly where the C++ has it, the tests in front written as the C++ writes them, the function in the local-ret form, and `// TODO(port): <question> <file>:<line>` on its own line above the reset. Status `unknown`.

**Open questions** (the design does not decide these):
1. **A reset that accepts OB_INIT_TWICE from an `init()` the design turns into a constructor.** src/oblib/lib/allocator/ob_fixed_size_block_allocator.h:383-385 clears OB_INIT_TWICE from `fsb_allocator_.init(...)` because that allocator "is a singleton class", and src/storage/ddl/ob_ddl_redo_log_writer.cpp:260-263 calls `speed_handle_item_.init()` on every `limit_and_sleep` and takes OB_INIT_TWICE as "already inited". These are the only reset rows within three lines of OB_INIT_TWICE (from migration/: `awk -F'\t' 'NR>1{print $1":"$2}' inventory/sweep/reset.tsv | while IFS=: read f l; do awk -v s=$((l-3)) -v e=$l 'NR>=s && NR<=e' ../$f | grep -q OB_INIT_TWICE && echo "$f:$l"; done`). RULEBOOK 2.1 drops the OB_INIT_TWICE check along with `init()`, and s2-errors.md 2.2 rule 7 keeps a type's not-initialized state only where a caller tests OB_NOT_INIT; neither covers a caller that tests OB_INIT_TWICE. Conservative translation: keep the call, the test and the reset as written, which needs the callee to keep an `init()` that can answer OB_INIT_TWICE, with the TODO(port).
2. **A `bool` named ret that receives a code.** src/storage/memtable/mvcc/ob_mvcc_trans_ctx.cpp:1947-1950 declares `bool ret = OB_SUCCESS;`, stores the code of `link_and_get_next_node` in it and returns it, so any failure comes back as 1. s2-errors.md 2.2 rule 5 only chooses between `ObResult` and `i32`. Conservative translation: keep `ret: bool` with the conversions written out (`ret = <call>.is_err();`), return the C++ value `ret as i32` (RULEBOOK 2.1: an `int` return that is not an OB code stays `i32`), mark `BUG(port):` for the lost code (RULEBOOK 2.10, the BUG rule) and `TODO(port):` for the question. Its one caller drops the result (src/storage/memtable/mvcc/ob_mvcc_ctx.cpp:220).
3. **Where a `macro_rules!` made from a `#define` with a reset takes the caller's ret.** s2-errors.md 2.3 says the variable is named at the call, and the check macros take it first (`ck!(ret, a, b)`, `ox!(ret, s)`, `ov!(ret, c, OB_X, k)`), but no rule fixes the place for other macros. Conservative translation: the first argument, as `ck!` has it, with one TODO(port) on the `macro_rules!` definition, not one per use. The reset rows of that body stay `confirmed`: their meaning does not depend on the answer.

## 10. Pre-classification

Before the fan-out, a script may propose a value for each row from the row itself and a window of its file: the reset line, the 8 lines above it and the 6 below it, each with a trailing `\` and any `//` comment removed. A proposal is only a starting point: the classifier still reads the site as sections 3 to 5 say, keeps or replaces the value, and writes the evidence. Each rule below names the check its proposal needs.

The rules use five terms:
- **Block:** the window lines above and below the reset, each way up to the first line indented less than the reset.
- **Opener:** walking up from the reset, skipping blank lines, comment lines and lines indented as deep as the reset or deeper, the first line indented less than the reset. A line holding only `{` gives way to the line above it, and a condition over several lines is read from its `if (` to its `{`. The rules take the reset's opener and that opener's own opener, both within the 8 lines above; for an `else` or `else if` opener they also read the earlier `if` and `else if` lines of its chain, at its indentation, up to 32 lines up.
- **Named codes:** an `OB_[A-Z0-9_]+` (with any `common::` prefix) compared by `==` with `ret` or with a name ending in `_ret` (`hash_ret`, `tmp_ret`, `saved_ret`; `OB_X == (tmp_ret = f())` included), in an `if` or `else if` opener, in the reset line's own one-line `if` or ternary, or as a `case OB_X:` opener; and, when an opener is `else` or `else if` or the reset line is `} else if (FALSE_IT(ret = OB_SUCCESS))`, every code that the chain's earlier conditions compare with such a name by `!=`.
- **Store into ret:** `ret =` (not `==`), `OB_FAIL(`, `OB_SUCC(` or `FAILEDx(` around anything but `ret` alone, or a check macro (`OZ(`, `OX(`, `CK(`, `OV(`, `OZX1(`, `OZX2(`, `COVER_SUCC(`).
- **Copy of ret:** a line `<name> = ret;` whose name is not `ret`.

The rules, in order; the first that holds gives the proposal:
1. **NOT_TRANSLATED:** the file, or for a `file:a-b` entry the row's line, is in not-translated.tsv's `files` column. The value is decided; the classifier only writes the row (4.1).
2. **DECLARATION:** the reset line matches `^\s*(const\s+)?[A-Za-z_][\w:]*\s+ret\s*=\s*(common::)?OB_SUCCESS\s*;`, the word before `ret` being a type, not `return`, `else` or `case`. 4. **CHOSEN_BY_FLAG:** the construct is "code chosen by a flag" and there is no named code. Check that ret holds OB_SUCCESS whenever the ternary runs; a callee's code there sends the row to section 4's values 7-15 (src/sql/engine/basic/ob_json_table_op.cpp:1670 is IGNORED).

8. **ALREADY_SUCCESS:** there is no named code, and one of these holds: the code line just above the reset is `int ret = OB_SUCCESS;` or `INIT_SUCC(ret);`; the reset is the first statement under an `if` opener whose condition does not mention `ret` and whose code line above is that declaration; the opener's whole condition is `OB_SUCC(ret)` or `OB_SUCCESS == ret`; or the opener is `else`, or an `else if` whose condition does not mention `ret`, at the end of a chain in which one earlier condition is only `OB_FAIL(<call>)` or `OB_SUCCESS != (ret = <call>)` and no other mentions `ret`. 9. Otherwise, no proposal.

A script never proposes the other values, since each needs code beyond the window: OWN_DEFAULT (ret's declaration and every path from it), RESTORED_LATER and COPIED_OUT (where the copy goes, whether it comes back, and the holder's type, lock and threads), RETRY (the loop and its exit), OTHER_CODE (only once values 10-13 are ruled out at the producer), IGNORED (only once every other value is) and UNKNOWN.
